# Перенос Roboland MAX на Netlify Free

Готовый проект-прокси для существующей Google Таблицы + Google Apps Script.

## Что сохраняется

- Все вкладки школ и привязки `chat_id`.
- Триггер Apps Script каждые 10 минут.
- Отправка текстов и сообщений с изображениями через существующий алгоритм.
- Webhook входящих событий MAX по прежнему отправляется непосредственно в Google Apps Script.

## Шаг 1. Зарегистрироваться

Откройте https://app.netlify.com/signup и создайте аккаунт. Выберите тариф Free (0 долларов).

## Шаг 2. Загрузить проект

1. Распакуйте архив `roboland_max_netlify.zip`.
2. Войдите в Netlify под своим аккаунтом.
3. Откройте https://app.netlify.com/drop .
4. Перетащите **всю распакованную папку** `roboland_max_netlify` (не ZIP и не внутреннюю папку `public`) в Drop zone.
5. Дождитесь завершения Deploy. Получите свой сайт, например `https://my-roboland-proxy.netlify.app`.

Документация: https://docs.netlify.com/manage/projects/add-new-project/

## Шаг 3. Секретная настройка

Откройте проект Netlify → `Project configuration` → `Environment variables` (названия могут немного отличаться) → Add variable.

- Key: `MAX_BOT_TOKEN`
- Value: **текущий действующий токен вашего MAX-бота**. Берите его из вашей защищённой конфигурации Apps Script/Script Properties. Не присылайте токен в чат и не добавляйте его в файл с кодом.

Если доступны настройки области применения, переменная должна быть доступна `Functions`.

**После создания/изменения переменной нужен повторный deploy**. Для проекта, созданного вручную: снова загрузите ту же распакованную папку в область Drop zone раздела `Deploys` проекта.

## Шаг 4. Проверить, что серверная функция установлена

Откройте:

`https://ВАШ-САЙТ.netlify.app/api/health`

Ожидаемый ответ:

`{"status":"running","tokenConfigured":true,"tlsVerification":"enabled"}`

Если `tokenConfigured:false`, проверьте переменную окружения и сделайте повторный deploy.

Открытие `https://ВАШ-САЙТ.netlify.app/api/me` в обычном браузере вернёт `401 PROXY_UNAUTHORIZED` — это нормально: браузер не знает токен.

## Шаг 5. Временно проверить через Google Sheets

1. **Не удаляйте Yandex Cloud и не отключайте старые публикации, пока не протестировали Netlify.**
2. Выберите время вне массовых публикаций. На время переключения лучше временно отключить триггер отправки или провести тест на копии Google Таблицы — иначе посты могут отправляться через новый сервер без проверки.
3. Сохраните старое значение `Настройки` → `API_BASE_URL` отдельно, чтобы быстро откатиться.
4. Впишите в `API_BASE_URL`:

`https://ВАШ-САЙТ.netlify.app/api`

Никаких `/me` или `/` на конце.

5. Обновите страницу Google Sheets.
6. Нажмите `MAX автопостинг → Проверить токен бота`. Ожидаемый результат: `Код: 200` и данные бота MAX.
7. Проверьте **один тестовый текстовый пост** и **один тестовый пост с картинкой** в отдельной тестовой беседе MAX, используя стандартные команды Apps Script.
8. Если обе отправки сработали, восстановите триггер и продолжайте работу. Yandex Cloud отключайте только после нескольких удачных публикаций.

Вкладки школ и даты публикаций менять не нужно.

## Если проверка `/me` выдаёт 502

Посмотрите JSON и логи функции Netlify → `Logs` / `Functions`.

- `reason: ENOTFOUND`, `ETIMEDOUT`, `ECONNRESET`: сеть / доступ из зарубежного хостинга.
- `reason: UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `SELF_SIGNED_CERT_IN_CHAIN` или `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`: корневой сертификат MAX отсутствует в Node. Сначала нужно добавить доверенный корневой сертификат Минцифры, а затем повторить запрос.
- `401 PROXY_UNAUTHORIZED`: Netlify получил токен, отличный от того, который отправляет Apps Script, либо токен отсутствует.
- `404 PROXY_ROUTE_NOT_ALLOWED`: неверный путь или схема `/api`.

Поддерживается добавление корневого сертификата через переменную `MAX_EXTRA_CA_PEM_BASE64` (PEM сертификат, кодированный Base64), без изменения кода. **Не загружайте недоверенные сертификаты и не отключайте HTTPS-проверку для постоянной работы.**

В коде есть аварийный флаг `ALLOW_UNVERIFIED_MAX_TLS=true`, отключающий проверку TLS только для `platform-api2.max.ru`. В обычной настройке **не устанавливайте** эту переменную: это создаёт риск перехвата токена и сообщений.

## Безопасность

- MAX API расположен по фиксированному адресу `platform-api2.max.ru`; прокси не пересылает запросы на произвольные домены.
- Доступ к API прокси защищён проверкой того же токена MAX, который уже отправляет Apps Script. Токен хранится также в закрытой переменной Netlify `MAX_BOT_TOKEN`.
- Не публикуйте токен, не отправляйте его скриншотом, не добавляйте его в GitHub или ZIP.
- URL Netlify можно использовать только после теста доступа к MAX. На зарубежном хостинге могут быть сетевые ограничения и ограничения на передачу данных.
- У Netlify Functions есть ограничение на размер запроса/ответа: по этой причине сами **картинки продолжают загружаться через Apps Script на выданный MAX URL**, а через Netlify передаются только команды. Если именно этот прямой upload-URL недоступен Apps Script, понадобится отдельная доработка.

## Структура проекта

- `netlify.toml` — перенаправляет `/api/*` на серверную функцию.
- `netlify/functions/max-proxy.mjs` — прокси к MAX API.
- `public/index.html` — публичная стартовая страница без секретов.
- `tests/proxy.test.mjs` — проверки маршрутов и авторизации (`npm test` — для разработчика).

Составлено на основе последнего предоставленного кода `Roboland_MAX_Autopost_MultiSchool_v3_SSL.gs`.
